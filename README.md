# Chickinfry Go

The Go client runtime for Chickinfry. Go SDKs generated by the Chickinfry CLI
(`chik generate`) import this module; most applications use the generated client
rather than calling this package directly.

**Status: in development.** Go is not marked as a supported language until
verification is complete.

## Requirements

Go 1.26 or later (`go.mod` declares `go 1.26.0`).

## Installation

```sh
go get github.com/chickinfry/chickinfry-go
```

## First call

```go
package main

import (
	"context"
	"errors"
	"fmt"

	"github.com/chickinfry/chickinfry-go"
)

func main() {
	transport, err := chickinfry.NewHTTPTransport("https://api.example.com")
	if err != nil {
		fmt.Println(err)
		return
	}

	var output struct {
		Status string `json:"status"`
	}
	err = transport.Invoke(context.Background(), "service.operation", map[string]string{}, &output)
	if err != nil {
		var operationErr *chickinfry.OperationError
		if errors.As(err, &operationErr) {
			fmt.Println("operation failed:", operationErr.Code, operationErr.Status)
			return
		}
		var clientErr *chickinfry.ClientError
		if errors.As(err, &clientErr) {
			fmt.Println("client failed:", clientErr.Code, clientErr.OutcomeUnknown)
			return
		}
		fmt.Println(err)
		return
	}
	fmt.Println(output.Status)
}
```

`NewHTTPTransport` returns an `HTTPTransport` and accepts HTTPS origins or an explicit IP loopback HTTP origin such as
`http://127.0.0.1:8787`; other origins are rejected. `WithBearer` returns a copy
of the transport that sends a bearer token, and `WithSession` attaches a
`SessionStore` for automatic one-time refresh. Use `NewHTTPTransport(origin, WithTimeout(d))` to override the default 30-second request timeout; nonpositive durations are rejected.

Use a shared `MemoryStore` to keep a session in memory:

```go
store := new(chickinfry.MemoryStore)
signed, err := transport.WithSession(store)
```

Generated authentication calls adopt successful login credentials in the
memory store and clear matching credentials after successful logout. Set can
also adopt an existing credential bundle. Public operations can run with an
empty store. Clients bound to the same store pointer share one refresh, then each retries its
original request once. Rejected refreshes clear only matching credentials; a
concurrent `Set` or `Clear` prevents a late refresh from overwriting the session.
The store does not persist credentials or coordinate across processes. Scope
each store to one origin. Custom
`SessionStore` implementations retain responsibility for serializing refreshes,
saving login and refresh results, and clearing only matching credentials.

## Local failures

Local validation, transport, decoding, and session storage failures return
`*ClientError`. Use `errors.As` to distinguish them from `*OperationError`,
which represents a validated server rejection. `ClientError.Code` uses these
stable lowercase values:

| Code | Meaning |
| --- | --- |
| `unauthenticated` | A required session is absent or invalid, or a refresh was blocked. |
| `invalid_argument` | Invalid input or configuration before sending. |
| `failed_precondition` | Storage or transport state requires caller action. |
| `resource_exhausted` | Request, response, or storage capacity exceeded. |
| `deadline_exceeded` | The call exceeded its deadline. |
| `canceled` | The caller canceled the call. |
| `unavailable` | A connection or transport failure. |
| `data_loss` | Stored data is corrupt. |
| `unimplemented` | The requested environment or storage version is unsupported. |
| `internal` | An invalid response, refused redirect, or broken invariant. |
| `unknown` | A local failure without a more specific classification. |

`Status` is a pointer to the actual HTTP status when a response was received,
or nil otherwise. A timeout does not manufacture HTTP 504, and cancellation
does not manufacture HTTP 499. `OutcomeUnknown` warns that the operation may
have executed: do not automatically replay it. A failed or uncertain refresh
keeps its token blocked rather than trying it again. `errors.Is` and
`errors.As` can inspect a wrapped cause; that cause may contain raw network
details, so display the safe `ClientError.Error()` message instead.

The code catalog does not imply support for persistent device storage.
Generated clients expose their typed operations through `CreateClient(transport)`.

## Server initialization

Generated entries can register a startup callback with
`server.RegisterStartup(func() (server.Handler, error))`. Registration does not
execute it. `server.Initialize()` waits for the callback once per instance and
publishes its non-nil handler only on success. Concurrent callers wait for the
same result. Returned errors, panics, and nil handlers become a remembered
`operation_failed` failure; the instance does not retry or dispatch business code.
`server.InitializeStatus()` returns 0 on success or 500 on failure for an entry's
initialization export. Host boot wiring belongs to the generated entry and loader.
`Handle` also checks initialization after validating the request frame.

In Go, setup runs once per instance (currently once per request). Avoid expensive initialization.

Register exactly one of `Register` or `RegisterStartup` during entry initialization,
before initialization or dispatch. Existing `Register(handler)` entries continue
to work without a startup callback. Registration is not a hot-swap API, and
`Handle` retains its request-owned buffer contract.

Operations can return `server.NotImplemented()` for HTTP 501 with
`{"error":"not_implemented"}`. The existing `server.ErrNotImplemented` also works,
including through error wrapping. Unexpected errors and all panics
remain sanitized HTTP 500 failures. Startup failures always return 500, even if
the callback returns `ErrNotImplemented`.

Use `server.NotFound()`, `server.InvalidInput()`, `server.Conflict()`, or
`server.Forbidden()` for common operation failures. For a custom failure, return
`&server.OperationError{Code: "out_of_stock", Status: 409}`. Dispatch validates the mutable value before sending it;
statuses outside 400 through 599 or an empty code become `operation_failed`/500.
Its `Error()` method returns only the code. The server type is distinct from the
client runtime's received `OperationError`; remote errors are not trusted as
public server failures. Unavailable authentication operations return `not_found`/404.
The former `server.Error` name has no compatibility alias.

Authentication continues to expose only `server.Session` (session ID and public
user ID/email). Protected dispatch must reject a missing session before invoking
business code; public dispatch may pass a nil session. Session lookup errors must
propagate on both paths. With platform authentication enabled, `Request.Public()`
removes credentials from a copy; without it, pass the original request through.

## Native server sessions

Native server sessions use a 30-day idle timeout and no absolute lifetime by
default. Successful refresh rotates credentials and renews the idle deadline;
access requests and failed refreshes do not renew it. Access tokens expire after
15 minutes or at the family deadline, whichever comes first.

Validate a custom policy before registering the application, then pass the
immutable value to each request's authentication runtime:

```go
policy, err := auth.NewSessionPolicy(2592000, 0)
if err != nil {
	panic(err)
}
authentication := auth.New(connection, hooks, policy)
```

Both inputs are integer seconds. Idle timeout must be between 3600 and 31536000;
absolute lifetime accepts the same range or 0 to disable it. A shorter absolute
lifetime is valid. Existing sessions use the current policy at their next check,
so shortening a timeout or enabling a cap may require users to sign in again.
Apply the additive authentication migration for `first_login_at` and
`last_renewed_at` before upgrading the runtime. Valid legacy sessions transition
on successful refresh; expired or revoked sessions remain rejected.

## Signup rate limit

Pass the normalized `auth.rate_limits.signup` settings as
`auth.Options.SignupRateLimit` to `auth.NewWithOptions`. Nil fields use the defaults.

| Option | Environment variable | Default |
| --- | --- | --- |
| `Signal` | `AUTH_RATE_LIMITS_SIGNUP_SIGNAL` | `email` |
| `Max` | `AUTH_RATE_LIMITS_SIGNUP_MAX` | 10 |
| `WindowSeconds` | `AUTH_RATE_LIMITS_SIGNUP_WINDOW_SECONDS` | 900 |

`email` limits each normalized email address independently. `global` shares a
signup limit across the authentication database. Map `auth.rate_limits.signup: off`
to `Signal: new("off")` to disable the signup limit. Environment variables override
individual options. Hosted WASM must supply `auth.Options.LookupEnv` using
`request.Environment` for allowlisted bindings. A failed lookup returns an
error. Set the count and window to positive integers
(up to 2,147,483,647 attempts and 31,536,000 seconds). Environment integers use
decimal digits without padding. Invalid settings fail before database I/O.
A full signup bucket returns `rate_limited` (429). Existing buckets retain their
expiry.
